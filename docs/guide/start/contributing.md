1. 本指南面向所有希望向本站提交资源、修正信息或参与维护的社区成员，无论技术背景如何均可参与。

2. 本站收录范围限定为 Minecraft 生态相关资源，包括整合包、模组、插件、工具、服务端软件、服务器、资源包、光影包、地图、数据包、社区群组、内容创作者等，不收录与 Minecraft 无关的内容。

3. 提交资源前请确认该资源具备可访问的公开信息页面（如 GitHub 仓库、CurseForge/Modrinth 项目页、官方文档或稳定的群聊入口），不接受仅存在于私人网盘或临时链接中的资源。

4. 每份资源提交必须包含以下信息：资源名称、作者/运营者、适用平台（Java 版/基岩版/双端）、支持的 Minecraft 版本、加载器类型（如适用）、一句话简介、官方来源链接、最后验证日期。信息缺失或无法核实的提交将被退回要求补充。

5. 资源简介应客观描述功能与用途，禁止使用夸大宣传用语（如「最强」「第一」「必装」等），禁止包含引流、广告、付费推广等商业性质内容，但允许标注资源本身的付费情况（如「部分功能需赞助解锁」）。

6. 服务器与群聊类资源的提交需额外提供：服务器类型（生存/PvP/RPG 等）、在线规模估算、群规摘要或链接、是否要求实名/付费入群。本站保留对存在欺诈风险、收费不合理或管理混乱的群组拒绝收录的权利。

7. 如发现已收录资源存在信息过时（如下架、停止维护、链接失效、版本不再支持）、描述错误或归类不当，欢迎通过 Issue 或 Pull Request 提交修正，修正时请在说明中注明信息来源或验证方式。

8. 提交方式分为两类：熟悉 Git 操作的用户可直接 Fork 仓库后提交 Pull Request，遵循现有文档的 Front Matter 格式与目录结构；不熟悉 Git 的用户可通过「关于」页面提供的表单或邮箱提交资源信息，由维护者代为录入。

9. Pull Request 提交后需等待维护者审核，审核周期通常为 3 至 7 个工作日。审核内容包括：信息完整性、格式规范性、资源可访问性验证、分类准确性。维护者可能要求补充材料或调整分类，请保持沟通渠道畅通。

10. 提交即视为您确认该资源不侵犯第三方知识产权，且您有权代表该资源提交收录申请。若提交内容涉及抄袭、盗用、未经授权的搬运或违反 Minecraft EULA 的行为，本站将拒绝收录并保留追溯责任的权利。

11. 维护者有权根据资源质量、社区反馈、生态变化或本站运营方向调整收录标准，已收录资源可能因不符合更新后的标准而被迁移分类、标记弃用或移除，此类调整不另行通知原作者。

12. 所有贡献者提交的内容默认采用与本站一致的版权协议（通常为 CC BY-SA 4.0 或 MIT，以仓库 LICENSE 文件为准），提交即视为同意该协议。若您希望保留其他版权要求，请在提交时明确声明。

13. 对于持续贡献且质量稳定的社区成员，本站维护者可能邀请其加入协作维护团队，获得直接编辑权限。成为维护者后需遵守更高的审核标准，不得未经审核自行收录存在利益关联的资源。

14. 如对贡献流程、审核结果或收录标准存在异议，请通过 Issue 或官方联系渠道提出，维护者将在 7 个工作日内予以回应。禁止因个人纠纷在提交信息中夹带攻击、诽谤或无关内容。
