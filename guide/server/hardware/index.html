硬件

约 2434 字大约 8 分钟

2026-06-30

硬件需求没有一个标准答案，主要是看你的服务器类型、版本、玩家数量和玩法，这是需要动态调整的，不是固定死的。

简单说一下优先级：CPU > 内存 > 存储 > 网络

除此之外，还得看你是云服务器还是自建服务器。云服务器方便弹性扩容，自带公网 IP 和基础防护，适合公开服；自建性能可控，但需处理公网 IP、端口转发、停电/断网等麻烦。

1. 处理器（CPU）

跟大多数游戏一样，MC（Java版）是出了名的吃单线程性能（单核性能）。

    Core 1  [████████████████████] 100%  ← 主线程(Tick/实体/AI)
    Core 2  [██░░░░░░░░░░░░░░░░░░]  12%  ← 网络/保存
    Core 3  [██░░░░░░░░░░░░░░░░░░]   8%  ← 插件异步任务
    Core 4  [█░░░░░░░░░░░░░░░░░░░]   5%  ← 闲置围观
    ...
    Core 16 [░░░░░░░░░░░░░░░░░░░░]   0%

虽然说像Paper这样的服务端已经剥离了一些次要任务到其他线程，主线程依然是瓶颈。

所以说CPU选择的原则就是高主频 + 高 IPC（每时钟周期指令数）。

具体选择的话，主要有两个方面要看：

  1. 架构

最新几代的高性能桌面/服务器架构（如 Raptor Lake 及其后续、Zen 4/Zen 5 及后续），IPC 差距不大，选主频高的。

  1. 核心数

原版或小型插件服 2~4 核足够；中型 4~6 核；大型多世界/高日活服建议 8 核以上，用于分担异步任务（世界保存、网络压缩、插件逻辑等），但主线程仍看单核。

注意

能不选的话就不选老旧低频的至强（如 E5-2650 v2 之类的），因为它虽然核心多，但主逻辑会卡顿，服务器很难保持20 TPS。

注

基岩版的服务端用的是 C++ 编写，多线程优化好，可以有效利用多核。同等玩家规模下，对单核性能要求是低于 Java 版的，多核低主频的服务器 CPU 也能跑得很好。所以不要把基岩版服务器的硬件需求跟Java版搞混。

参考表：

玩家规模选择
小型（10 人以下）i3 / R3 就可以
中型（20~50 人）建议 i5-14600K / R5 7600X 以上
大型（100 人+）i7-14700K / R7 7800X3D 或更高，有条件优先上X3D

如果实在是想用多线程性能（多核性能）强点的CPU（比如Threadripper），可以看看PaperMC团队开发的Folia服务端项目。

相关信息

Folia 将世界切分成多个独立的区域（Region），每个区域由一条专属线程负责自己的 tick。各区域同时并行运行。跨区域实体（如玩家移动、矿车传送）由全局调度器接手，在区域之间安全移交，不再阻塞整个服务器。

虽然说Folia目前兼容性不是很好，但是如果只跑Folia的话，多核高主频CPU反而会更香。

2. 内存（RAM）

MC原版本身不吃内存，2GB内存的老电脑都能跑，吃内存的罪魁祸首主要是加载的区块、玩家数据、实体、模组/插件。

这里分Java版和基岩版两种情况讲。

Java版

Java版吃内存的主要有三个地方：服务端、玩家、模组/插件。

  • 服务端：约 600MB~1.2GB 基础占用
  • 玩家：视距 10~12 时，约 80~200MB / 玩家。视距越大，人均内存上涨明显。玩家越多，吃的内存就越多。
  • 模组/插件：一个大型整合包（200多个模组）空载就可能吃掉 4~6GB，玩家加入后吃更多。

参考表：

规模分配方案
小型物理内存 4~8GB；服务端分配 2~4G
中型物理 16GB；服务端 6~8G
大型/高日活物理 32GB；服务端 10~16G

不过需要注意的一个点是：不要无脑分配过多的内存！

主要原因就在于Java本身是有个垃圾回收（GC）机制，它如果在超大堆内存上工作，就会引发长时间的“stop-the-world”卡顿。客户端同理，内存分配多了，玩着玩着就会突然卡死一下下。

暂停时间
  ^
  |                             ___
  |                           _/   \___  <- 巨大堆导致长时间STW
  |                         _/
  |                       _/
  |                    __/
  |             _____/
  |      ______/
  |   __/
  | _/  建议区间 (4-12GB)
  |/______________________________> 堆内存大小
                  ^       ^
                 10GB    64GB

如果没特殊情况，分配4~12GB内存就够用了。哪怕你机器有64GB的内存，也建议只给服务端分出10G左右。

基岩版

内存需求要比Java版低很多，同等人数通常只需 Java 版的 1/3~1/2，一个 20 人基岩服可能 1~2GB 内存就够。

  20人服务器内存需求对比

  Java版   |████████████████████████|  ~4-6 GB
  基岩版   |██████████|                ~1-2 GB

注意

记得定时重启服务器，服务器硬件配置再好也避免不了内存泄漏（内存碎片），可以选择在每天的凌晨时间段重启服务器。

3. 存储

存储比较好理解，MC里的世界生成、区块加载保存、玩家频繁进出区域，都会产生大量随机读写。

一般是不建议拿机械硬盘（HDD）来开服务器，能用固态硬盘（SSD）就尽量用固态硬盘，因为机械硬盘开服务器哪怕两三个玩家探索新地形都会导致严重卡顿，所以平时都是建议拿来当数据备份盘。

这里建议大家把系统和服务端都放在 SSD 上。

有条件上NVMe M.2 SSD，没条件上SATA SSD，SATA已经能解决大部分场景，而NVMe对区块生成（尤其是快速飞行加载地形）提升比较明显，但是不强求。

  NVMe SSD   [■■■■■■■■■■]  200+ chunks/s
  SATA SSD   [■■■■■■■░░░]  100  chunks/s
  HDD        [■■░░░░░░░░░]   15  chunks/s

提示

如果想降低实时硬件压力，可以试试世界预生成这一方案，就是提前用指令或插件跑完地图，生成文件后，玩家跑图时不再触发实时生成，这样做可以大幅降低 CPU 和磁盘峰值。

模组端可以试试Chunky或Chunk-Pregenerator，插件端可选Chunky。

然后就是空间需求。

一个长期游玩的原版世界存档可能膨胀到 10~30GB（视玩家活动和预生成范围）。模组服生成更多结构，地图更大。建议至少预留 50~100GB 可用空间。

       Minecraft 世界存档磁盘占用比例
      0 GB                    100 GB
      ├──────────────────────────┤
原版  │▶▶▶·····················│  10~30 GB
模组  │▶▶▶▶▶▶▶▶▶▶········│  50~100 GB
预留  |···················▶▶▶▶|  ≥50 GB

▶ 指代占用区间 · 指代空闲

最后是备份问题，可以选择用一些面板服/云服务器自带的备份功能，如果不想用或者说你是本地开服，也可以考虑用上面提到过的机械硬盘备份服务器。

别问为什么用机械硬盘，因为便宜量还大 =D

4. 网络

网络这一环也很重要，一堆小白自建服务器的时候忽略网络，结果人一多就瞬移、打不掉方块。需要重视。

带宽

每个玩家约消耗 0.1~0.5 Mbps 上行带宽（视距、实体数量影响），10 人同服的话，至少需要 5~10 Mbps 上行；50 人则需要 20~50 Mbps 稳定上行。

如果是家宽，就需要注意“共享带宽”，上行常被限速（如 30Mbps），实际可用需留冗余。

DDoS防御

如果是小型公开服，一般是不需要DDoS防御的，但如果规模做大了，那么它就是刚需。

要整还是建议上云服务商的高防 IP 或专业机房，因为家庭宽带极易被打断。

延迟

服务器地理位置应靠近大多数玩家，延迟 50ms 以内手感最好。选择云服务器时注意机房位置。

提示

只要服务器位置在大陆地区，延迟基本都大差不差，只要服务商的网络带宽不是特别shit就行

如果是本地同城自建，那么延迟就可以做到 10ms 以内。

5. 参考配置

速查表：

场景CPU内存(系统)存储网络上行
好友联机 (2-10人)i3/R38 GB120G SATA10 Mbps
中型服 (20-50人)i5/R516 GB512G NVMe50 Mbps
大型服 (100+人)i7/R7+32-64 GB1T NVMe200+ Mbps
模组服 (10-30人)i7/i9 K32 GB1T NVMe30 Mbps

以下是详细配置说明：

  1. 朋友联机（2~10人）
  • CPU：现代双核四线程，主频 3.5GHz+（如 Intel N100/N305 小主机，或 i3/R3）
  • 内存：4~8GB（服务端分配 2~4G）
  • 存储：120GB+ SATA SSD
  • 网络：10Mbps 上行

注

甚至可以跑在树莓派 4/5（超频 + 散热 + SSD），但 4~5 人就到极限。

  1. 中型社区服（20~50人）
  • CPU：6 核 12 线程，单核最大频率 4.8GHz+（i5/R5 级别）
  • 内存：16GB（服务端 6~8G）
  • 存储：512GB NVMe SSD
  • 网络：50Mbps 上行，低延迟机房
  1. 大型公共服（100+在线）
  • CPU：8 核 16 线程高端消费级或服务器级（i7/R7/R9 或高频至强 W 系列），单核性能仍要强劲
  • 内存：32~64GB（服务端可分多实例，单个实例 8~12G 或更多）
  • 存储：1TB NVMe 高性能 SSD + HDD 冷备份
  • 网络：200Mbps~1Gbps 上行，专线 BGP 线路，高防保护

注

这套方案一般采用多服务器群组，即群组服（BungeeCord/Velocity），各子服分担压力，硬件叠加。

  1. 大型模组服（如大型科技+魔法整合包，10~30人）
  • CPU：重点是高主频，一般可以选解锁功耗墙的带 K / X 型号
  • 内存：建议 32GB 物理内存，给服务端分配 8~16GB，视整合包怪物和模组数量
  • 存储：模组服启动及区块加载 IO 密集，NVMe 是刚需，并预留足够空间存动态模组配置
